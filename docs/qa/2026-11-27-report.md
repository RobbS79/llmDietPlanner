# QA Prod Report — 2026-11-27

**VERDICT: NO-GO**

Post-deploy QA of prod commit `c27149a` (PR #121, carrying the Uvařto launch from PR #120). Two FAILs, both in the launch's own front-door flow:

1. **Opening any recipe from the search results crashes the whole app.** Clicking a result card's photo or name opens the recipe sheet, which throws React error #31 and replaces the page with the full-screen "NĚCO SE POKAZILO." error boundary. Reproduced on every recipe tried in the browser (262, 544); the API returns the crashing shape for 13 of 13 recipes sampled.
2. **The "Bez masa" example chip returns fish and chicken dishes.** The literal phrase "bez masa" falls back to text search every time (3 of 3 attempts) and shows salmon, "Domácí rizoto" (chicken) and "Rizoto s kuřecím masem".

Everything else in the launch works: search, picking dishes, the tray, `/nakup`, the signup sheet, the plan sheet, deals display, mobile layout.

- Base URL: https://eatalnicek.eu

Checks ran through Node scripts on the `e2e/` Playwright install with `chromiumSandbox: false`. Scripts and screenshots are in `/tmp/claude-0/-opt-llmDietPlanner/5928c8c5-78b9-4d2a-ac19-bc0ebe987580/scratchpad/qa/`.

## Warnings (not scored as FAIL)

- **Bot check is off on prod.** The 4th and later searches from one IP were answered without a Turnstile challenge, so the Turnstile keys are not set and only the rate limits (20/day, 6/min per IP) protect search. The spec lists this as an owner action.
- **Meta Pixel suppresses one funnel event.** With consent given, the console warns "You are attempting to send a restricted event. The event was suppressed." It appeared each time right after clicking "Nákupní seznam", so it is most likely `InitiateCheckout`; I inferred that from timing, not from the request. Worth a look in Events Manager before running ads.
- **Same four recipes for many different searches.** "krabičky do práce", "bezlepková večeře", "Lehčí jídla na hubnutí", the gibberish query and the "Bez masa" fallback all lead with the same three salmon dishes plus Domácí rizoto. For "Lehčí jídla na hubnutí" that includes a 735 kcal and a 635 kcal dish.
- **Repeated category photos.** Several results share one stock image (four identical salmon photos on the "Rychlá večeře" results). Some category images contradict the dish in the sheet API: "Pečená zelenina s balzamikem" uses `mlete-maso.webp`, "Utopenci" uses `kure.webp`, "Domácí salsa" uses `ryba.webp`.
- **Implausible kcal.** "Sekaná pečeně" shows 1938 kcal per portion; "Svíčková na smetaně" 1080 kcal.
- **Truncated deal names.** The strip cuts names to two words: "Smetana ke" (Smetana ke šlehání), "Vepřová panenská"; card badges show "V akci: slunečnicový a 6 další" and "V akci: vepřová a 2 další".
- **Near-duplicate list lines.** `/nakup` lists "pepř" and "černý pepř", "sůl" and "mořská sůl", "česnek 3 ks" and "česnek 2 stroužky" separately.
- **`/nakup` loading state.** For under a second the page shows the "Ostatní" heading and both buttons with no rows and no loading text.
- **Stale copy outside the launch pages.** `/jak-to-funguje` still describes the old flow (profile at registration, "Zvolíte zemi a město"). `/o-nas` says the tool "ukáže přesně, kolik budou stát v obchodech", while the site now states "Ceny neuvádíme". The consent banner, `/login` and the public recipe page still use formal "vy" while the launch pages use "ty".
- **Error screen leaks a raw English React message** to visitors.
