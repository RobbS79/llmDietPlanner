# Diet Planner Backend Feature

This Django app provides the backend API for users to submit dietary goals and receive personalised meal plans generated by LLMs.

## Features

- **Dietary Goal Creation**: Users can submit prompts with their dietary goals and restrictions
- **GDPR Compliant**: PII data (prompts, dietary restrictions) is encrypted at rest
- **Async Processing**: LLM generation handled by Celery workers for performance
- **Localization**: Supports CEE currencies (PLN, CZK, HUF, EUR) and i18n
- **Standardised API**: Consistent JSON responses following project standards

## Setup Instructions

### 1. Install Dependencies

```bash
pip install -r requirements.txt
```

### 2. Generate Encryption Key (Required for GDPR)

Generate a Fernet encryption key for encrypted fields:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Add this key to your `.env` file:

```env
FIELD_ENCRYPTION_KEY=your-generated-key-here
```

**Important**: Generate a new key for production and store it securely. Do not use the default dummy key.

### 3. Configure Celery & Redis

Add to your `.env` file:

```env
CELERY_BROKER_URL=redis://localhost:6379/0
CELERY_RESULT_BACKEND=redis://localhost:6379/0
```

Start Redis (if not already running):

```bash
# Using Docker
docker run -d -p 6379:6379 redis:7-alpine

# Or install locally (Ubuntu/Debian)
sudo apt install redis-server
sudo systemctl start redis
```

### 4. Create Database Migrations

```bash
python manage.py makemigrations diet_planner
python manage.py migrate
```

### 5. Start Celery Worker

In a separate terminal:

```bash
celery -A llm_diet_planner_project worker --loglevel=info
```

## API Endpoints

### Create Dietary Goal

**POST** `/api/goals/`

**Authentication**: Required (Session Auth)

**Request Body**:
```json
{
  "prompt": "I want to lose 5kg in 2 months while maintaining muscle mass",
  "dietary_restrictions": "No gluten, lactose intolerant",
  "currency": "PLN",
  "language_code": "pl"
}
```

**Response** (201 Created):
```json
{
  "status": "success",
  "data": {
    "goal_id": 1,
    "status": "pending",

  "error": null
```

## Architecture

### Models

- **DietaryGoal**: Stores user dietary goals with encrypted PII fields
  - `prompt` (encrypted): User's dietary prompt
  - `dietary_restrictions` (encrypted): Allergies/restrictions
  - Status tracking: `pending`, `processing`, `completed`, `failed`
  
- **DietaryPlan**: Generated plan linked to a goal
  - `meal_ideas` (JSON): LLM-generated meal suggestions
  - `shopping_list` (JSON): LLM-generated shopping list
  - `total_price`: Calculated by Django (not LLM)

### Task Processing

1. User submits prompt → `DietaryGoalCreateView`
2. Creates `DietaryGoal` with status `pending`
3. Triggers Celery task: `process_dietary_goal_task`
4. Task updates status to `processing`
5. LLM generates meal ideas and shopping list
6. Creates `DietaryPlan` with LLM output
7. Updates goal status to `completed`

**Note**: Price calculation and availability checks are handled separately by Django using database queries (not by LLM).

## GDPR Compliance

- Sensitive PII fields (`prompt`, `dietary_restrictions`) are encrypted at rest using `django-encrypted-model-fields`
- Encryption key stored in environment variable (not in code)
- User data is linked to authenticated user accounts
- Timestamps use ISO-8601 format for audit trails
